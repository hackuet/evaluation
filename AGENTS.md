# Autonomous Agent Instruction Manual: HACK Evaluation & Ingestion Workflow

This document outlines the strict technical protocol and workflow for autonomous AI coding agents operating on the **HACK (Hardware Acceleration Club of KUET)** technical evaluation repository.

---

## 1. Mission & Core Directives

When tasked with processing a new assignment:
- **Given Inputs**:
  1. A student submission CSV (e.g. from Google Forms / Google Classroom export).
  2. An assignment problem statement / question description.
- **Evaluation Model Architecture**:
  - All AI technical evaluations must be performed using **Gemini 3.8 Flash (Medium Thinking)**.
- **Strict Privacy Mandate**:
  - **Only `roll` is used as the student identifier**.
  - **Zero Names & Zero Emails**: Student names and email addresses must NEVER be stored in CSV files, markdown evaluation reports, source code, data files, UI markup, or git commit messages.
  - No hashing or encoding—simply use plain roll numbers (`52509028`, `52531013`, `52503088`).
  - Git commit author/committer must always be configured as `hackuet <hackuet@users.noreply.github.com>`.

---

## 2. Directory & File Organization Standards

All assignments follow a strictly structured, predictable directory layout grouped by academic batch:

```
├── .gitignore                   # Ignores video files (*.mp4, *.webm, etc.) & node_modules
├── index.html                   # Single-page technical leaderboard application
├── style.css                    # Monotonic minimalist engineering stylesheet
├── app.js                       # Client-side dynamic ranking & CSV parsing engine
├── data.js                      # Pre-bundled offline dataset generated by generate_data.py
├── generate_data.py             # Compiler script that merges CSVs + code into data.js
├── README.md                    # Public documentation
├── AGENTS.md                    # This agent instruction manual
└── <batch>/                     # e.g., 2k25/
    ├── template.csv             # Empty starter template for new grading sheets
    └── <assignment-folder>/     # e.g., assignment-1/
        ├── <assignment>.csv     # Active grading CSV (e.g., assignment-1.csv)
        ├── QUESTION.md          # Exact assignment question statement verbatim
        ├── RUBRIC.md            # Official scoring criteria (150 base + bonus pool)
        ├── EVALUATION_PROMPT.md # Evaluator subagent prompt (specifying Gemini 3.8 Flash Medium)
        ├── submissions/         # Code files organized strictly by student roll
        │   ├── <roll_1>/        # e.g., 52509028/
        │   │   ├── No_01.ino
        │   │   └── Task-2 PWM.txt
        │   └── <roll_2>/        # e.g., 52531013/
        │       └── Task-1 LED blinking.ino
        └── evaluations/         # Individual technical audit markdown reports
            ├── <roll_1>.md      # e.g., 52509028.md
            └── <roll_2>.md      # e.g., 52531013.md
```

## 3. Step-by-Step Ingestion & Evaluation Pipeline

Follow this 8-step workflow whenever an assignment CSV and problem description are provided:

### Step 1: Initialize Assignment Directory & Documentation
1. Determine the target batch (e.g., `2k25`) and assignment identifier (e.g., `assignment-2`).
2. Create directory paths:
   - `<batch>/<assignment-folder>/submissions/`
   - `<batch>/<assignment-folder>/evaluations/`
3. Write `<batch>/<assignment-folder>/QUESTION.md` containing the assignment question **verbatim** ("as is").
4. Author `<batch>/<assignment-folder>/RUBRIC.md`:
   - Base total is 150 points (typically: Participation 55, In-Time 15, Core Tasks 75, Inline Comments 5).
   - Bonus pool (+75 points) for hardware registers, multitasking, direct port manipulation, and robotics simulations.
5. Author `<batch>/<assignment-folder>/EVALUATION_PROMPT.md`:
   - State model: **Gemini 3.8 Flash (Medium Thinking)**.
   - Embed exact rubric guidelines and objective grading criteria.

### Step 2: Sanitize & Format the Grading CSV
1. Read the input student CSV.
2. **Immediately strip `name` and `email` columns**.
3. Align columns to match the official format:
   ```csv
   roll,batch,status,submission_time,on_time,drive_link,participation,in_time,task1_inst,task1_llm,task2_inst,task2_llm,task3_inst,task3_llm,docs_inst,docs_llm,bonus_inst,bonus_llm,instructor_note,student_comment
   ```
4. Save the file to `<batch>/<assignment-folder>/<assignment-folder>.csv`.

### Step 3: Download & Place Code Submissions
1. For each student row in the CSV:
   - Extract the Google Drive URL.
   - Download submitted code files (`.ino`, `.c`, `.cpp`, `.py`, `.txt`, `.md`, `.pdf`).
   - Place downloaded files into:
     `<batch>/<assignment-folder>/submissions/<roll>/`
2. **Strict Media Constraint**:
   - Do NOT commit video files (`.mp4`, `.webm`, `.mov`, `.avi`). These are excluded by `.gitignore`.
3. If a student's Google Drive is permission-locked:
   - Set `status` in CSV to `Pending Drive Access`.
   - Award participation credit (55 pts) and in-time credit if submitted on time, and mark code tasks as pending re-evaluation.

### Step 4: Run AI Technical Evaluation via Gemini 3.8 Flash Medium
1. Evaluate each student's code using **Gemini 3.8 Flash (Medium Thinking)** against the rubric:
   - **Task 1 (Concurrency)**: Check for non-blocking state machine (`millis()`) vs sequential blocking (`delay()`).
   - **Task 2 (Software PWM)**: Check microsecond timing, duty cycle calculations, integer overflow bugs (e.g. 16-bit signed AVR int `time * value`).
   - **Task 3 (Sonar Reader)**: Check hardware acceleration via timer capture / interrupts vs CPU polling vs forbidden `pulseIn()`.
   - **Code Quality**: Check pin naming, variable types, and inline comments.
   - **Bonus Tasks**: Verify direct register manipulation (`DDRx`, `PORTx`, `TCCRx`, `OCRnx`) and simulation setups.
2. Generate `<batch>/<assignment-folder>/evaluations/<roll>.md`:
   - Header: `# Objective Technical Evaluation Report: <roll>`
   - Top metadata: `- **Student Roll**: <roll>` (never include email or name).
   - Score Summary Table with Instructor, LLM, and Combined scores.
   - Detailed task-by-task technical analysis and code reviews.
3. Update the CSV with the computed `task*_llm`, `docs_llm`, and `bonus_llm` scores.

### Step 5: Compute Hybrid Scoring
The club uses a 60/40 hybrid formula combining human instructor grading with AI subagent audits:
$$\text{Task Mark} = (\text{Instructor Mark} \times 0.6) + (\text{LLM Subagent Mark} \times 0.4)$$
$$\text{Bonus Mark} = (\text{Instructor Mark} \times 0.6) + (\text{LLM Subagent Mark} \times 0.4)$$
Ensure concise, objective transparency notes are recorded under `instructor_note`.

### Step 6: Update Metadata & Recompile Data Store
1. Open `generate_data.py`.
2. Ensure the new assignment is registered in `assignments_meta`:
   ```python
   {
       "id": "a2",
       "folder": "assignment-2",
       "code": "A-02",
       "batch": "<batch>",
       "title": "Assignment Title",
       "status": "Active",
       "deadline": "YYYY-MM-DD HH:MM",
       "baseMax": 150,
       "bonusMax": 75,
       "totalMax": 225,
       "rubric": { ... }
   }
   ```
   *(Note: `generate_data.py` automatically reads `QUESTION.md` from the folder and embeds it as `meta["question"]`).*
3. Execute the generator:
   ```bash
   python3 generate_data.py
   ```
   This updates `data.js` with all student submissions, code files, and questions.

### Step 7: Verify via Playwright
Before committing any changes:
1. Verify the local server is running on port 8080:
   ```bash
   python3 -m http.server 8080
   ```
2. Run Playwright verification script to assert:
   - Zero occurrences of student names or email addresses anywhere on the page or in modals.
   - Student roll numbers match expected records.
   - Dual-mode switching works (Cumulative vs Assignment view).
   - Assignment question section is displayed verbatim on the assignment page.
   - Profile modal, Audit modal, and Rubric modal function correctly.

### Step 8: Git Commit & Remote Deployment
1. Verify git user configuration:
   ```bash
   git config user.name "hackuet"
   git config user.email "hackuet@users.noreply.github.com"
   ```
2. Verify git status and diff:
   ```bash
   git status
   git diff
   ```
3. Commit and push:
   ```bash
   git add -A
   git commit -m "feat: add <assignment-name> evaluation and grades"
   git push origin main
   ```
4. GitHub Pages will automatically build and publish to `https://hackuet.github.io/evaluation/`.
